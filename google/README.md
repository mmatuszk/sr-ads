# Google

This folder is for Google Ads and Google conversion tracking work.

## Structure

- `data/` raw exports and source files
- `scripts/` Google Ads API reporting and management commands
- `config/` reporting definitions and operational guardrails when introduced
- `investigations/` dated technical and performance reviews
- `changes/` dated campaign and budget change logs

Keep all Google-specific API calls in this folder. New commands should default
to read-only behavior. Commands that change live campaigns must use explicit
operator confirmation, channel guardrails, and a dated record in `changes/`.

Shared audience generation and run notes live in `../audiences/` because the same customer lists can support Google, Pinterest, and future advertising platforms.

## API Authentication

Google Ads uses the same user-based Application Default Credentials (ADC)
pattern as the existing SR Google Drive integration. OAuth credentials stay in
the standard local ADC file and are loaded by the Google client library; they
are not committed to this repository.

### Shared Credential Model

The local Google authorization has three separate pieces:

| Purpose | Local file or account | Notes |
| --- | --- | --- |
| OAuth client | `~/.config/sr-automation/google_client_secret.json` | Existing SR desktop OAuth client; reuse it for Drive, Sheets, Ads, and Merchant |
| User grant | `~/.config/gcloud/application_default_credentials.json` | Generated by `gcloud`; shared Application Default Credentials |
| Google Ads routing | `~/.config/sr-ads/google_ads.json` | Developer token plus manager and operating customer IDs |

Keep both local JSON configuration files outside Git and restrict them to the
local user:

```bash
chmod 600 "$HOME/.config/sr-automation/google_client_secret.json"
chmod 600 "$HOME/.config/sr-ads/google_ads.json"
```

The shared OAuth grant must always include all five scopes:

```text
https://www.googleapis.com/auth/cloud-platform
https://www.googleapis.com/auth/drive
https://www.googleapis.com/auth/spreadsheets
https://www.googleapis.com/auth/adwords
https://www.googleapis.com/auth/content
```

Reauthorizing ADC replaces the previous grant. Do not request only the Ads or
Merchant scope: omitting another shared scope can break existing SR
integrations that use the same ADC file.

### Google Platform Setup

The shared Google Cloud project's display name is `SR Google Automation`. Its
immutable project ID remains `sr-gem-knowledge-publisher`. The canonical access
and scope runbook is maintained in
`sr-knowledge/docs/technical/google-automation-access.md`.

Confirm the following before local authorization:

1. The Google Ads API is enabled in the Cloud project.
2. Google Merchant API is enabled before Merchant Center integration work.
3. The OAuth consent configuration includes both
   `https://www.googleapis.com/auth/adwords` and
   `https://www.googleapis.com/auth/content` in Data Access.
4. The existing SR desktop OAuth client is available at
   `~/.config/sr-automation/google_client_secret.json`.
5. The OAuth user has access to the Google Ads operating account.
6. The operating account is linked to the Google Ads manager account.

Google Ads also requires a developer token created in a Google Ads manager
account. Store the token and account IDs outside Git in:

```text
~/.config/sr-ads/google_ads.json
```

Restrict that file to the local user with mode `600`. Its expected shape is:

```json
{
  "developer_token": "REDACTED",
  "login_customer_id": "4422175447",
  "customer_id": "5626118344"
}
```

Account roles:

- `4422175447` is the Silk Resource Ads Manager account. It owns the developer
  token and is the `login_customer_id` for manager-routed calls.
- `5626118344` is the linked operating account that contains the campaigns and
  is the `customer_id` for normal reporting and management calls.
- The OAuth user also has direct access to the operating account, so direct
  calls are available as a diagnostic fallback.

The developer token, OAuth client, and customer IDs have different jobs. The
developer token remains associated with the manager account; it does not need
to be recreated when ADC expires or when the operating customer ID is queried.

### Authorize or Reauthorize ADC

Run this command from any directory for both first-time authorization and
reauthorization:

```bash
gcloud auth application-default login \
  --client-id-file "$HOME/.config/sr-automation/google_client_secret.json" \
  --scopes "https://www.googleapis.com/auth/cloud-platform,https://www.googleapis.com/auth/drive,https://www.googleapis.com/auth/spreadsheets,https://www.googleapis.com/auth/adwords,https://www.googleapis.com/auth/content"
```

Sign in as the SR Google user and approve the requested Drive, Sheets, Google
Ads, and Merchant access. The command writes the resulting user grant to:

```text
~/.config/gcloud/application_default_credentials.json
```

Never edit that generated ADC file manually. Rerun the authorization command
when the client library reports:

```text
Reauthentication is needed. Please run `gcloud auth application-default login`
to reauthenticate.
```

An expired ADC grant is an OAuth issue, not a developer-token issue. Do not
reset the Google Ads developer token in response to this error.

## Verify API Access

First confirm that ADC can refresh without printing the access token:

```bash
gcloud auth application-default print-access-token >/dev/null \
  && echo "ADC refresh succeeded"
```

From the repository root, run the read-only verifier:

```bash
.venv/bin/python google/scripts/verify_google_ads_access.py
```

The normal path sends the manager account as `login_customer_id` and queries the
linked operating account. To test the OAuth user's direct account access without
the manager header, run:

```bash
.venv/bin/python google/scripts/verify_google_ads_access.py --direct
```

The manager-routed path was verified successfully after a full-scope
reauthorization on July 27, 2026. Both manager-routed and direct paths were
verified on July 16, 2026. The verifier reads account metadata and campaign
names/statuses only; it does not mutate Google Ads.

### Authentication Troubleshooting

| Error or symptom | Action |
| --- | --- |
| `RefreshError: Reauthentication is needed` | Rerun the full five-scope ADC authorization command above |
| `DEVELOPER_TOKEN_INVALID` | Recopy the token from the manager account API Center and preserve every character |
| Manager-routed request cannot find the operating account | Confirm `login_customer_id` is `4422175447`, `customer_id` is `5626118344`, and the account link remains active |
| Direct mode works but manager-routed mode fails | Check the manager-to-operating-account link and manager ID |
| API disabled or unavailable | Confirm the required API is enabled in the `SR Google Automation` project (`sr-gem-knowledge-publisher`) |

Do not solve an account-routing error by swapping the two customer IDs or
creating another developer token. The manager ID identifies the API login
context; the operating ID identifies the account containing the campaigns.

## Export Weekly Campaign Performance

Export the last `104` complete Monday-through-Sunday weeks for `Performance
Max-2` (campaign ID `20647427212`):

```bash
.venv/bin/python google/scripts/export_campaign_weekly_performance.py
```

The exporter excludes the current partial week and writes a campaign-level CSV,
a conversion-action detail CSV, and retrieval metadata under the dated
`google/data/campaign-performance/` folder. It is read-only. Use
`--campaign-id`, `--weeks`, or `--output-dir` to override the defaults.

For the Max-2 analysis, keep `SR Sales` and exclude the duplicate legacy
WooCommerce purchase action from the adjusted series:

```bash
.venv/bin/python google/scripts/export_campaign_weekly_performance.py \
  --exclude-conversion-action-name '[85ed] Google for WooCommerce purchase action'
```

This preserves the raw reported campaign and conversion-action files and adds a
`weekly-adjusted.csv` file. The metadata records the exclusion and method.

Review conversion-action detail before interpreting long-range ROAS. Historical
tracking migrations can leave more than one value-bearing purchase action active
in the same week and inflate Google Ads' reported conversion value. The export
metadata identifies weeks with such overlaps; raw values are not silently
adjusted.

## Compare WooCommerce And Shopify ROAS

Run the seasonally matched Max-2 comparison after exporting the weekly data:

```bash
python3 google/scripts/analyze_max_2_woo_vs_shopify.py
```

The analysis uses `SR Sales` for WooCommerce and `Google Shopping App Purchase`
for Shopify. It excludes the duplicate legacy WooCommerce purchase action and
October through December 2025, when the Shopify store was not fully set up. The
comparison aligns `28` complete January-through-July weeks in 2025 and 2026.

The reproducible reconciliation query is:

```text
google/config/reports/max-2-woo-vs-shopify.sql
```

Export weekly product-level Shopping performance when investigating feed or
catalog events:

```bash
.venv/bin/python google/scripts/export_campaign_product_performance.py
```

The default export covers Max-2 from January 5 through July 19, 2026 and writes
product attributes, impressions, clicks, cost, conversions, and conversion
value to the dated campaign-performance folder. The export is read-only and can
be large; the July 21 run contains `101,214` product-week rows.

The generated `performance-max-2-weekly-products.csv` is intentionally ignored
by Git because it is large and reproducible from the Google Ads API. Its small
metadata JSON remains tracked. To reproduce the July 21 analysis input exactly,
first complete the OAuth and developer-token setup above, then run from the
repository root:

```bash

  --start-date 2026-01-05 \
  --end-date 2026-07-19 \
  --output-dir google/data/campaign-performance/2026-07-21
```

Use the same command before rerunning
`google/scripts/analyze_max_2_woo_vs_shopify.py` in a fresh checkout. Override

### Developer Token Normalization Gotcha

Treat the developer token as an opaque string. A valid token can contain
punctuation such as hyphens or underscores. Never remove, replace, change case,
or otherwise normalize its characters.

Google Ads customer IDs are different: UI-formatted customer IDs may have
hyphens removed before API use. Normalize only `login_customer_id` and
`customer_id`, never `developer_token`.

Removing a hyphen from the developer token caused
`AuthenticationError.DEVELOPER_TOKEN_INVALID` even though the token copied from
the API Center was correct. Preserve the token exactly as issued.

- Use `56-90` days as the main budget and ROAS evaluation window.

## Product Segmentation Report

`scripts/generate_product_segmentation_report.mjs` converts a Google Ads
product-report XLSX export into a combined action report. The generator:

- calculates the account purchase CPA and uses `2 × CPA` as the significant
  spend threshold
- combines the high-spend/low-ROAS and significant-spend/zero-ROAS rules into
  one deduplicated `Exclude now` queue, while keeping margin review separate
- queries Shopify in batches for the canonical product metafield
  `order.type`
- carries the Google product `Item ID` and Shopify Product GID into every
  action sheet so rows can be matched in either platform
- appends `Shopify Order Type` to the source data and carries `Order Type`
  into every action sheet
- includes an order-type mix summary for the catalog, action queue, and
  exclude-now set

The Shopify lookup is read-only and is implemented by
`scripts/query_shopify_order_types.py`. It uses the existing
`sr-automation/config/automation.yaml` Shopify configuration and credentials.

Run the generator with the Codex workspace spreadsheet runtime:

```bash
ARTIFACT_TOOL_MODULE="/path/to/@oai/artifact-tool/dist/artifact_tool.mjs" \
node google/scripts/generate_product_segmentation_report.mjs \
  --input "/path/to/Product report.xlsx" \
  --output "/path/to/combined-product-segmentation-report.xlsx"
```

The supported `order.type` values currently include `standard`, `special`,
`special-2`, `custom`, `consultation`, and `sewing`. Missing metafields are
reported as `unassigned`; Google Ads products not found in Shopify are reported
as `not_found`.
